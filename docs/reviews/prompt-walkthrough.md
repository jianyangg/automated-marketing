# Instruction-only prompt walkthrough

October 13, 2026. Method: manually apply the supplied agent procedures to synthetic inputs and inspect the proposed outputs. This checks workflow clarity and factual restraint. It is not a runtime, clean-machine, provider, human-user, or marketing-outcome test.

## Case 1 — new local service, no assets or accounts

Input: [Harbor Repair fixture](../../examples/brands/harbor-repair/brand.md). Use [session start](../../prompts/session-start.md), [onboarding](../../prompts/onboard.md), [strategy](../../prompts/strategy.md), and [validation](../../prompts/validation.md).

### Resulting operating brief

**Goal:** more qualified routine-maintenance appointment requests.

**Known offer:** the synthetic brief describes commuter-focused routine tune-ups, puncture repairs, and appointment maintenance. No independent research has verified the business.

**Unknown:** location, real destination, request baseline, pricing, opening hours, capacity, current customer mix, and media rights/proof. No accounts or spending authority exist.

**Diagnosis:** insufficient evidence to select a channel or promise a booking increase. Offer/destination readiness and local reachability need checking before a posting plan.

**Priority:** validate the request path and the fit between the stated service and a reachable commuter audience. This outranks an automatic content calendar because location, capacity, and a real conversion destination are unresolved.

### First validation plan

| Field | Proposed value |
| --- | --- |
| Question | Can a relevant commuter understand and request the workshop's routine-maintenance service? |
| Evidence | Real location/service area, available appointment capacity, service details, booking destination, and any supplied customer observations |
| Method | Owner-supplied fact review and booking-path audit first; bounded public-language/alternative research after location is known; no new participant research |
| Source criteria | Current owner service material and actual public booking flow; no simulated interview counted as evidence |
| Tasks | Confirm essential facts; audit offer/CTA/form clarity; record objections/missing proof; propose one test |
| Operator effort | Provisional until the owner supplies available time; no invented capacity or cash budget |
| Authority | Private preparation only; no customer contact, account access, purchase, publication, or timer |
| Exit condition | Enough verified offer/destination context to choose a first distribution or conversion experiment |
| Observations | None yet; planned work is not completed research |
| Decision | Proceed with factual commissioning; defer channel/cadence selection |
| Distribution | Not applicable to this local validation stage |

### Reviewable production fallback

Provisional text concept: “A puncture repair or routine tune-up? Tell us what your bike needs when requesting an appointment.”

This is a draft idea grounded only in the fixture. It is not publication-ready: the destination, service wording, capacity, and owner review remain unresolved. A real asset brief can request a workshop-owned repair photo with permission; no generated image may be presented as the actual shop.

**Walkthrough result:** the procedures produce a complete validation work item and useful draft direction without an App Store field, prior marketing asset, social connection, fixed quota, false research result, or public action. Remaining work is explicit.

## Case 2 — exposure exists but conversion is uncertain

Synthetic input: an established product reports many impressions and few signups, but supplies no comparable denominator, traffic-quality breakdown, or observation window.

Expected strategy output: verify metric definitions/window/quality, inspect proposition and destination, then propose a specific comparison if the evidence supports it. Do not assert the landing page is the cause or increase posting automatically. A low-confidence conversion bottleneck remains a hypothesis. The attention budget remains provisional until supplied.

**Walkthrough result:** the strategy and learning prompts explicitly require these distinctions. Runtime measurement correctness remains covered by future T20–22 and T32.

## Case 3 — old strategy conflicts with current evidence

Synthetic input: supplied historical copy promotes an unavailable feature; a new audience/proposition replaces the previous strategy while some work is queued.

Expected output: preserve originals, mark historical claims unreviewed/contradicted, gate the unavailable feature, and identify incompatible campaigns/deliveries/policies. Hold future execution pending a deliberate retain/revise decision and appropriate authority. Do not delete remote posts or infer permission from historical publication.

**Walkthrough result:** onboarding, strategy, review, root guidelines, and T33 now specify the same behavior. Actual queue enforcement is unimplemented and must be tested in R2.

## Limits and follow-up evidence

These checks support the clarity of the supplied procedures. They do not prove Codex will always select the procedure correctly, a user will find setup easy, or a provider/worker will enforce it. Implementation must run the declared clean-clone, fixture, authority, recovery, and real-account commissioning suites. Real marketing effectiveness still requires a business-specific pilot.
