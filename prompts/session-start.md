# Session-start procedure

## Purpose

Recover the right context and choose useful work without depending on previous chats or an author's environment.

## Procedure

1. Read the repository README for current implementation status. Distinguish available instructions/templates from future runtime capabilities.
2. Classify the request as framework work, brand onboarding, strategy/research, production, review/execution, or learning.
3. If a brand is specified, resolve its folder/identity. If several are plausible and a write depends on selection, clarify before writing. A portfolio request may use aggregate brand briefs; it does not justify loading all private assets.
4. Use observed installed status/tools if available. Otherwise inspect only selected local artifacts. Never assume the proposed CLI, MCP, worker, external plugins, or personal runtime paths exist.
5. Read the selected brand's `index.md` as its concise operating brief/navigation: goal, verified-offer reference, active strategy/hypotheses, top opportunity, work in progress, blockers, pending owner decisions, and actual authority references. If absent, derive a provisional index from available records without inventing status or overwriting owner files. Apply section 10 of `docs/brand-workspaces.md` when creating/updating work.
6. Check current source/release freshness and any unresolved conflicting facts relevant to the task. Do not substitute old memory or historical campaign acceptance for current evidence.
7. Read the relevant workflow prompt and continue useful authorized work. Ask only essential missing questions, bundled when practical.

Before strategy or production, follow relevant decision/lesson links and inspect comparable prior work. Retrieve only what helps the present decision; record what should be reused, changed, avoided, or retested. Choose filing locations and maintain navigation as part of the task; the owner need not manage the workspace or prescribe the marketing method.

For evidence-dependent decisions, route to `prompts/research.md`; search proactively using available tools. Check the access, date, applicability, and revision of any method/evidence being reused. This framework does not run surveys, interviews, recruitment, or synthetic customer panels. LLM concept critique follows `prompts/concept-evaluation.md` and cannot establish demand.

## First session with no brand

If the owner asks for business marketing, identify or request the business folder and minimum business context. If the owner asks to build/review this framework, perform that task directly; onboarding a fictional customer is not required unless testing.

## Missing runtime

Use manual, clearly labeled files for research, proposed decisions, drafts, and change packs. Preserve originals and use dated/versioned outputs. State that transactional execution/receipts remain unavailable. A Markdown note saying “approved” is not a secure execution grant.

## Output

A short statement of the useful next action or completed result. Show a context recap only when it resolves uncertainty; do not repeat a large onboarding brief every session.
