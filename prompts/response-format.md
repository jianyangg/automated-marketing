# Operator communication and deliverable format

## Operator chat

Lead with the useful decision, completed work, or material finding. Default to two to six lines, with a link to the complete artifact when detail is substantial. Use a short list only when it improves scanning. Avoid ceremonial headings, recapping every tool call, generic encouragement, or repeating unchanged status.

Explain a material unknown only when it changes interpretation or the next action. Identify exact missing information or authorization; do not ask for redundant confirmation. Distinguish proposed, prepared, attempted, authorized, scheduled, published, verified, and unavailable.

A normal update contains the outcome, the decisive reason/evidence, and the next required action if any. It need not use fixed field labels. A final reply is self-contained and links to the deliverable.

## Publishable business artifacts

Write for the intended customer/reader in the selected brand or owner voice. Keep them self-contained. Exclude tutoring addressed to the owner, conversation history, assistant attribution, internal approval requests, tool/implementation details, and research process commentary.

Internal campaign manifests, evidence, hypotheses, permission state, and measurement notes are separate from outward-facing copy. Synthetic examples, material limitations, required disclosures, and source attribution appear in customer content only where needed for accuracy and the audience's decision.

## Internal work artifacts

Use compact readable Markdown for briefs/decisions and validated structured data when an implemented tool requires it. Keep one responsibility per file. Link sources close to factual internal claims and distinguish facts from hypotheses/estimates. Use relative repository links and portable paths in distributable framework files; real private paths stay private.

Do not fabricate executable commands, grants, receipts, metrics, or status. Preserve original inputs and version revised work.

Choose the appropriate existing brand research/campaign/task record before creating a new file, following section 10 of `docs/brand-workspaces.md`. Persist material decisions and useful outputs, not every exchange. Keep the brand index current with links to active work and relevant history; outward-facing deliverables remain separate from these internal records. File organization is part of the agent's work, not another task assigned to the owner.
